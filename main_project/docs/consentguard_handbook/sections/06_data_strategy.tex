\chapter{Dataset strategy}

\section{The rule: change data to solve a target problem, not to chase a larger number}

A new dataset may improve a class or deployment domain, but its score is not directly comparable with the existing Visual Redactions score. Dataset size, ontology, image distribution, annotation policy, and metric implementation all change the meaning of the number.

Visual Redactions remains the frozen comparator because it connects the new work to the original privacy-localization problem \citep{orekondy2018visual}. The target-domain collection answers a different question: whether the complete bundle works on general and India-first mobile/social photographs.

\begin{truthbox}[Dataset admission rule]
No dataset enters training without a source URL, licence or use-right record, checksum, ontology mapping, source/contributor group, duplicate audit, and documented split policy. If the licence cannot be confirmed, the pixels stay outside the training repository.
\end{truthbox}

\subsection{Per-image metadata that must travel with every sample}

Every record needs a stable image ID, original source URL or consent record, licence, retrieval date, SHA-256, normalized pixel hash, contributor or capture group, ontology version, split group, annotation version, and withdrawal status. Every instance needs class, geometry, visibility/occlusion, size bucket, difficulty flags, annotator, adjudication status, and source provenance. These fields are part of the dataset specification because they prevent leakage and make a result reproducible.

\subsection{The critical distinction: training versus validation}

Public datasets supply representation and variety; Target-2K supplies deployment evidence. Do not use the same target image in pretraining, calibration, qualitative regression, or the locked test. Keep a source/capture group in one split, and maintain a private ledger for directly collected material.

\section{Recommended use by specialist}

\subsection{Face}

Use pretrained YuNet first. Evaluate on WIDER FACE hard conditions and Target-2K. Fine-tune or replace only if target-domain recall cannot reach the gate. Avoid face-recognition datasets because identity recognition is outside scope and introduces unnecessary biometric risk.

\subsection{Plate}

Use the Indian plate dataset for India-specific training after rights verification. Add licensed general examples from Open Images. CCPD may initialize plate features, but its Chinese plate distribution cannot measure Indian performance. Construct hard negatives from vehicle fronts/backs without visible plates, headlights, grilles, stickers, signs, and rectangular objects.

\subsection{Printed text}

Benchmark PaddleOCR on TextOCR-style scene images and Target-2K. Use TextOCR polygons for pretraining or fine-tuning if the provider misses small/rotated text. Track original Open Images IDs and licence metadata. Add target examples for posters, screens, receipts, IDs, packages, street signs, and mixed Indic/Latin scripts.

\subsection{Handwriting}

Use IAM and IIIT data for representation and recognition pretraining, then fine-tune localization on camera-captured target images. Word crops alone are insufficient because the deployment problem includes finding writing inside a full scene. Synthesize phone-like pages through perspective warp, shadows, blur, glare, compression, clutter, and partial crops, but always validate on real staged/consented images.

\subsection{Other private objects}

Reserve BIV-Priv-Seg as an external generalization benchmark first. It specifically exposes small, non-salient private objects and difficulty recognizing negative images. Do not merge it immediately into training; otherwise its value as independent evidence disappears.

\section{Licensing and privacy ledger}

For each source asset, record:

\begin{itemize}[leftmargin=6mm]
  \item canonical source URL and retrieval date;
  \item author/contributor when available;
  \item licence identifier and a local copy/hash of the licence text;
  \item allowed research, commercial, modification, and redistribution uses;
  \item whether the image itself and annotation have different licences;
  \item consent/release record for directly collected images;
  \item original file SHA-256 and normalized pixel SHA-256;
  \item takedown or withdrawal procedure; and
  \item allowed storage location and access roles.
\end{itemize}

Open Images includes image URLs, authors, rotation, and licence information, but its own documentation warns that individual licence status should be verified \citep{openimagesv7}. Treat that warning as an engineering requirement, not a footnote.

\section{Duplicate control}

Run duplicate checks before splitting:

\begin{enumerate}[leftmargin=7mm]
  \item exact byte hashes;
  \item normalized pixel hashes;
  \item perceptual hashes at several distances;
  \item embedding-based nearest-neighbor review for resized/cropped/recompressed copies;
  \item shared source URLs and contributor IDs; and
  \item burst or capture-sequence identifiers.
\end{enumerate}

All members of a duplicate/source group enter the same split. When two public datasets share Open Images sources, cross-dataset duplicate checks are required.

\section{What should not be collected}

Do not scrape real private IDs, medical prescriptions, addresses, signatures, or phone screenshots merely because they are technically visible online. Use staged or fictional content wherever possible. When realistic private content is necessary, obtain explicit participant consent, minimize retention, restrict access, and support withdrawal.

The project should demonstrate privacy engineering through its own data behavior.

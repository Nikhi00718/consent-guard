\chapter{The end-to-end architecture}

\section{The simple mental model}

Think of ConsentGuard as a careful inspection line, not one all-knowing model:

\begin{enumerate}[leftmargin=7mm]
  \item Prepare one trustworthy image representation.
  \item Ask several specialists what they see.
  \item Convert their answers into one evidence language.
  \item Apply provider-specific safety thresholds and merge overlaps.
  \item Show the proposals and uncertainty to a person.
  \item Enforce consent and release rules.
  \item Burn approved redactions into new pixels.
  \item attack the exported result independently.
  \item Export only if every required condition passes.
\end{enumerate}

\section{Input normalization}

All providers analyze the same \file{NormalizedImage}. The ingest step should:

\begin{itemize}[leftmargin=6mm]
  \item reject unsupported or malformed files with explicit reason codes;
  \item decode with resource limits to avoid decompression bombs;
  \item apply EXIF orientation once;
  \item convert to a fixed RGB pixel representation;
  \item record original dimensions and normalized dimensions;
  \item calculate a cryptographic pixel hash; and
  \item retain metadata findings separately from the pixel tensor.
\end{itemize}

Providers must not independently rotate or resize without returning the inverse transform. In the current design they receive normalized pixels and report original normalized-image coordinates.

\section{Framework-independent contracts}

\begin{lstlisting}[language=Python,caption={Conceptual public contracts.}]
EvidenceProvider.analyze(NormalizedImage) -> list[Evidence]
ThresholdRegistry.get(provider, privacy_class) -> ThresholdRule
EvidenceFusion.combine(list[Evidence]) -> ReviewCandidateSet
AssuranceService.inspect(RenderedAsset) -> AssuranceReport
ReleasePolicy.decide(candidates, consent, assurance) -> ReleaseDecision
\end{lstlisting}

An \file{Evidence} record requires:

\begin{itemize}[leftmargin=6mm]
  \item stable evidence ID and source detection ID;
  \item provider name and provider version;
  \item privacy class from the system ontology;
  \item image width and height;
  \item box, polygon, or mask geometry;
  \item confidence bounded to $[0,1]$;
  \item uncertainty flags; and
  \item enough provenance to explain why a fused candidate exists.
\end{itemize}

A \file{ThresholdRule} records provider, class, score threshold, minimum size, geometry expansion, mask dilation, experimental status, and whether review is mandatory. Manual command-line overrides must appear in the audit record.

\section{Logical parallelism, physical sequencing}

The providers are logically independent branches, but the laptop implementation runs them one at a time. This avoids loading several GPU-heavy frameworks simultaneously on a 4 GB RTX 3050. The orchestrator records provider errors and unavailable states instead of turning them into empty detections.

The execution order should be deterministic:

\begin{enumerate}[leftmargin=7mm]
  \item broad Mask R-CNN;
  \item face provider;
  \item plate provider;
  \item printed-text provider;
  \item handwriting provider;
  \item barcode provider; and
  \item metadata provider.
\end{enumerate}

CPU-only providers may later overlap safely, but concurrency is an optimization, not part of the V1 correctness contract.

\section{Release decisions}

The public decision values are:

\begin{description}[leftmargin=52mm,labelwidth=48mm,style=multiline]
  \item[\file{ALLOW\_REDACTED}] Approved redacted pixels passed every required assurance check.
  \item[\file{HOLD\_FOR\_REVIEW}] Candidates, uncertainty, conflicts, or assurance findings require correction.
  \item[\file{HOLD\_FOR\_CONSENT}] Relevant consent state is unknown, absent, or inconsistent with the requested export.
  \item[\file{REJECT\_EXPORT}] The requested output cannot satisfy the active policy, or a hard failure makes safe export impossible.
\end{description}

Every decision includes stable reason codes suitable for tests and audit. Human-readable wording may change; reason-code behavior must not change silently.

\section{Why this architecture is safer than a monolith}

One large model would simplify the marketing diagram but create several engineering problems: incompatible datasets, hidden trade-offs, difficult score calibration, expensive retraining, and reduced explanation. The evidence-provider architecture isolates failure domains and preserves the ability to compare alternatives.

After V1, a shared-backbone or distilled model can be evaluated as an optimization. It must reproduce or improve the candidate recall and leakage gates of the specialist bundle, and it must retain uncertainty and provenance. Until then, the multi-model bundle is the model.

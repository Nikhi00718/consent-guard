# Technical audit: reviewer interface (2026-09-18)

Scope: `src/App.tsx`, `src/MaskEditor.tsx`, `src/styles.css`, `index.html`, plus the "Found" overlay colours in `consentguard/stage_05_review_export/api/sessions.py`. Personal mode, every screen (empty, photo added, scanning, cover check, result).

How it was measured:
- axe-core 4 (WCAG 2.0/2.1/2.2 A and AA plus best practice) on 8 screen and size combinations: desktop 1440x900 and phone 390x844.
- Keyboard tab walk with focus-ring check; focus position after each screen change.
- Touch-target sizes on a touch-emulated phone; a single-finger stroke synthesized over Chromium's DevTools protocol.
- Text scaled to 200% at 1280px; reduced-motion emulation; contrast ratios computed from the tokens.
- Playwright end-to-end suite, Vitest unit suite, backend `stage_05_review_export` pytest suite, production build.

Not tested: physical phones, pinch gestures, Firefox and Safari, screen readers by ear (announcements were checked structurally).

## Implementation integrity verdict

Pass. The interface expresses one product-specific system (see `DESIGN.md`): warm charcoal grounds, one china-marker accent, a cover preview that matches the saved file, and plain-language status copy. A manual pass against the banned-pattern list (eyebrow labels, side-stripe borders, gradient text, glows, glyph icons, decorative monospace) found none. No automated pattern detector was run.

## Findings and fixes

| Sev | Finding | Where | Impact | Fix |
|-----|---------|-------|--------|-----|
| P1 | Hidden file input had no accessible name (axe `label`, critical) | `App.tsx` photo input | Screen readers announced an unnamed control | `aria-label="Choose a photo"` |
| P1 | Page spilled 200px sideways with text at 200% | `.easel` min-height plus aspect-ratio | Horizontal scrolling for low-vision users (WCAG 1.4.4, 1.4.10) | `min-width: 0` on the easel; breakpoints moved from px to em so layout follows the browser text size |
| P1 | Focus dropped to `<body>` when the check screen opened | `App.tsx` phase change | Keyboard and screen-reader users lost their place | Heading of each new screen receives focus |
| P1 | Brush-size slider lost its name between 861px and 1100px | `.brush-size span` hidden | Unnamed slider (WCAG 4.1.2) | `aria-label="Brush size"` on the input |
| P2 | Uploading, scanning and saving were silent to screen readers | `App.tsx` | No feedback while waiting | One persistent `role="status"` region |
| P2 | Reduced motion killed every animation, including spinners | `styles.css` | Waiting looked frozen | Targeted rules: scan line, print entrance, skeletons and corner slides stop; spinner slows to 2.4s; colour changes stay |
| P2 | Touch targets of 32 to 40px on phones | tools, view switch, chips, quiet buttons | Mis-taps | 44px on coarse pointers |
| P2 | Gesture state could stick after pointer cancel or window blur | `MaskEditor.tsx` | Stuck pan or paint after an alt-tab or an interrupted touch | `onPointerCancel` and a window `blur` handler reset it |
| P2 | Cover layer re-rendered on every pointer move | `MaskEditor.tsx` | Lag with many strokes | Cover memoised; only the ring and loupe layer redraw |
| P3 | Colour literals outside the tokens; canvas colours duplicated | `styles.css`, `MaskEditor.tsx` | Drift risk | New tokens (`--line-strong`, `--easel-hover`, `--scrim`, `--readout`); canvas reads tokens from CSS |
| P3 | "Found" view used the old teal palette | `sessions.py` `_COLORS` | Off-palette screen | Marker, safelight, fixer, paper, stop |
| P3 | Paste listener re-registered on every render | `App.tsx` | Minor churn | Registered once per screen |
| P3 | Toolbar declared `role="toolbar"` without arrow-key navigation | `MaskEditor.tsx` | Mismatched screen-reader expectations | Now a labelled group |
| P3 | Large photos decoded on the main thread | three `<img>` | Jank on huge files | `decoding="async"` |

## Results after fixes

- axe-core: 0 violations on all 8 screen and size combinations.
- Contrast: body text 15.2:1, secondary 7.1 to 8.4:1, tertiary 4.9 to 5.6:1, marker on dark 6.9:1, text on marker 6.7:1.
- Keyboard: logical order (skip link, Choose photo, chips, Detectors), 2px marker focus ring on every stop.
- Touch: one-finger stroke paints and enables Undo without scrolling the page; every visible target is 44px or larger on touch screens.
- Text at 200%: no horizontal overflow, nothing clipped.
- Tests: Vitest 9/9, Playwright 3/3, backend reviewer pytest 46/46, production build passes.

## Known limits

- No pinch-to-zoom on touch screens; the zoom buttons cover it.
- Freehand painting has no keyboard equivalent. Path-based input is exempt under WCAG 2.1.1, and saving works without painting.
- Thumbnails reuse the full-resolution normalized photo. That's fine locally, but a downscaled preview would help very large files.
